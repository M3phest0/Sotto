## 4. 问题清单

### P0：可能丢失或破坏用户内容

#### P0-1 保存失败后“保存并关闭”仍然关窗

- 状态：**已修复**。`closeAfterSave` 在保存失败时保留窗口；`saveErrorRef` 记录最近一次保存结果。
- 位置：`src/editor/EditorApp.tsx`（`closeAfterSave`、`persistNow`）
- 现象：`await persistNow()` 的布尔返回值被忽略；只要没有进入冲突状态，保存失败（磁盘满、权限、文件被占用、原子替换失败）也会继续执行 `finishClose()`。
- 实测证据（浏览器 mock，用 6MB 文本触发 localStorage 配额）：

  ```
  QUOTA_SAVE_STATE   "保存失败"
  QUOTA_CLOSE_CALLED true
  ```

  即界面先显示“保存失败”，随后窗口仍然关闭。
- 影响：用户明确选择了“保存并关闭”，却在保存失败后失去全部未保存修改。
- 建议：`if (!(await persistNow()))` 时保留窗口、保留确认框并提示失败原因；同时清掉 `pendingRef`，避免下一次关窗继续超时。

#### P0-2 切换文件不处理未保存草稿

- 状态：**已修复**。原生选择器改为“先确认再打开”；mock 文件输入在读取后确认；冲突栏“重新加载”增加丢弃草稿确认。
- 位置：`src/editor/EditorApp.tsx`（`pickFile`、`handleFile`、`confirmSwitch`、`reloadFromDisk`）
- 现象（修复前）：`pickMarkdownFile()` 返回后直接 `applySnapshot(next)`，没有检查 `dirtyRef.current`，也没有确认框。冲突栏的“重新加载”同理，会直接丢弃当前草稿。
- 规格冲突：`Sotto.md:400` 明确要求“切换前处理未保存草稿”。
- 影响：用户正在编辑时点“选择文件”，当前草稿被新文件静默替换；自动保存若尚未触发，内容不可恢复（切换前的 5 分钟备份也可能没有）。
- 建议：文件选择返回后先走与关闭窗口相同的确认流程（保存 / 放弃 / 取消），确认后再切换。

#### P0-3 有选区时按 Tab 删除选中文字

- 状态：**已修复**。有选区时按行首缩进（支持多行），无选区时仍插入 4 空格。
- 位置：`src/editor/EditorApp.tsx`（`handleKeyDown` 的 Tab 分支）
- 现象（修复前）：`el.setRangeText('    ', start, end, 'end')` 直接替换选区。
- 实测：

  ```
  原文行：  "  - [ ] 子项一"
  选中“子项一”后按 Tab
  结果行：  "  - [ ]     "
  TAB_SELECTION_LOST true
  ```

- 影响：常见“选中一段文字后按 Tab 缩进”的操作会误删内容。属于原生 undo 可恢复，但用户通常不会预期文本消失。
- 建议：有选区时按行首缩进（可多行），无选区时才插入 4 空格。

### P1：规格要求未实现或日常使用受阻

#### P1-1 启动不恢复上次文件（`lastFile` 被忽略）

- 位置：`src-tauri/src/lib.rs:269-274`（`ensure_current`）；`AppState::new` 固定使用 `Documents\Sotto.md`
- 现象：`settings.lastFile` 只在 `pickFile` 里写入，启动时从不读取。
- 原生实测：把 `settings.json` 的 `lastFile` 指向临时文件并重启，组件仍显示 `Documents\Sotto.md`。
- 影响：用户每次启动都要重新选择文件；“最近文件”也因此失去意义。
- 建议：`AppState::new` 或首次 `ensure_current` 读取 settings 的 `lastFile`，失效时回退到 known folder 默认路径。

#### P1-2 组件位置从不保存/恢复

- 位置：`src/shared/desktop.ts:21-28`；`src-tauri/src/lib.rs` 无 `onMoved` 监听，`windowPosition` 只在“重置位置”里被清空
- 现象：拖拽调用 `startDragging()` 后没有记录窗口物理坐标；启动时也不应用 `windowPosition`。
- 原生实测：把窗口移动到物理坐标 `(600, 400)` 后，`settings.windowPosition` 仍为 `null`；重启回到默认位置。
- 规格冲突：`Sotto.md:454-461` 要求保存物理像素位置 + 显示器标识、拔插后夹回、重置到主屏右下角 24px。
- 建议：Tauri `onMoved` 防抖写入物理坐标；启动和显示器变化时夹回工作区；“重置位置”立即移动窗口，而不只是写设置。

#### P1-3 宽度设置 300–480 实际不生效

- 位置：`src/widget/widget.css:18-19`、`src-tauri/src/lib.rs:1223-1229`
- 现象：原生组件窗口固定 `384×520` 逻辑像素；深色/浅色主题下卡片 `max-width: calc(100vw - 24px)`，因此宽度最多 360px。亚克力主题下 `.theme-acrylic .widget-card` 为 `width: 100%`，宽度设置完全不参与。
- 实测（384×520 视口，`width: 480`）：

  ```
  NATIVE_WIDTH_BOX  {"width":360,...}
  ACRYLIC_WIDTH     384
  ```

- 规格冲突：`Sotto.md:258` 允许 300–480，并说明宽度由编辑窗口设置。
- 建议：按 `settings.width` 调整原生窗口内尺寸（或根据主题统一卡片宽度），并在应用启动/设置变化时同步窗口尺寸。

#### P1-4 在途保存时关窗会造成 `pendingRef` 永久卡住

- 状态：**已修复**。在途保存结束时无条件清除 `pendingRef`；是否补一次保存由 revision 比较单独决定。
- 位置：`src/editor/EditorApp.tsx`（`persistNow` 的 `finally`）
- 现象：保存进行中再次调用 `persistNow()` 只设置 `pendingRef=true` 并返回。若此时文本 revision 没有变化，在途保存的 `finally` 不会清除 `pendingRef`；`waitForSaveIdle()` 会一直等到 5 秒超时，提示“保存超时，请重试或选择放弃”。
- 触发条件：自动保存写入磁盘的瞬间点关闭 → “保存并关闭”。属于窄窗口竞态，但磁盘慢/杀毒扫描时更容易出现。
- 建议：在途保存完成时无条件清除 `pendingRef`（是否补一次保存由 revision 比较单独决定）；`closeAfterSave` 在超时后不要依赖 `pendingRef` 作为“有未落盘内容”的唯一信号。

#### P1-5 只读文件仍可编辑

- 位置：`src/editor/EditorApp.tsx:726-737`（textarea 只有 `disabled={booting}`），保存按钮在 `666` 被禁用
- 现象：超过 1MB/5000 行或 Windows 只读属性的文件会显示“只读展示”，但 textarea 仍可输入；自动保存因 `readOnlyReason` 直接 return，关闭时提示“文件为只读，无法保存。可以放弃修改或取消”。
- 影响：用户可以在一个永远无法保存的文件里输入大量内容，最后只能放弃。
- 建议：只读时给 textarea 加 `readOnly`（仍可滚动/复制），并在进入只读模式时提示。

#### P1-6 编辑器会用过期设置覆盖托盘刚改的设置

- 位置：`src/editor/EditorApp.tsx:204-227`（文件变化订阅）、`533-537`（`updateSettings`）、`src-tauri/src/lib.rs:464-485`（`save_settings`）
- 现象：订阅回调在磁盘文件哈希未变化时直接 `return`，因此托盘修改的 `locked/theme/autostart` 不会同步进编辑器的 `settings` 状态。之后用户在设置页改任意一项，`saveSettings({...settings, patch})` 会用旧的整份设置覆盖磁盘，把托盘的修改回滚。Rust 端只保护 `editorWindow` 字段。
- 影响：例如托盘刚锁定位置，编辑器里改字号会把 `locked` 改回 `false`。
- 建议：设置变化时也刷新编辑器本地设置（区分“文件内容变化”和“设置变化”）；或让 `save_settings` 只合并允许前端修改的字段。

### P2：体验、边界与一致性

#### P2-1 只有空任务时显示“全部完成”，进度却是 0/2

- 位置：`src/widget/WidgetApp.tsx:159-167`、`169-174`
- 现象：空任务计入 `allTasks`/进度，但被排除在 `content` 之外，导致 `visibleLines.length === 0` 且 `allTasks.length > 0`，于是显示“全部完成”。
- 实测：文档 `- [ ] \n- [ ] \n` → 进度 `0/2`，空状态与 footer 都是“全部完成”。
- 建议：空状态判断改成“没有可显示行且没有完成任务”，文案用“任务还没有文字 · 点铅笔打开编辑器”。

#### P2-2 隐藏已完成父任务后，其下普通文本行变成孤立行

- 位置：`src/widget/WidgetApp.tsx:76-79`
- 现象：过滤只作用于带 `task` 的行；普通文本行没有所属任务信息，父任务被 `hideCompleted` 隐藏后仍显示。
- 实测：`- [x] 完成父项\n  隐藏备注\n- [ ] 其他` → 显示 `隐藏备注`、`其他`，但“完成父项”不可见。
- 建议：为文本行记录最近的父任务/缩进归属，父任务隐藏时一并隐藏；或父任务有可见文本子行时保留父任务上下文。

#### P2-3 快速输入后点击预览里的任务，第一次点击被吞

- 位置：`src/editor/EditorApp.tsx:507-513`
- 现象：输入后 250ms 内 `renderedRevision !== revision`，第一次点击只提交预览并提示“预览已刷新，请再点一次”，勾选意图不生效。
- 实测：输入 `b` 后立即点击第一项，源码保持 `- [ ] ab`，出现提示。
- 建议：点击时先用当前 textarea 值重新解析，再按行号执行 toggle；或把点击意图排队到预览提交后执行。

#### P2-4 在父任务行末按 Enter 会把现有子任务改挂到新空任务下

- 位置：`src/editor/EditorApp.tsx:480-490`
- 实测：

  ```
  输入：- [ ] 父项
          - [ ] 子项一
            - [ ] 孙项
          - [ ] 子项二
  在“父项”行末按 Enter 后：
        - [ ] 父项
        - [ ]
          - [ ] 子项一
            - [ ] 孙项
          - [ ] 子项二
  ```

- 影响：新建的空任务插在父项和子项之间，按缩进规则成为子项的新父级；预览层级立即改变。用户想新增同级任务时很容易误操作。
- 建议：若当前行有子项，Enter 时把新任务插到整棵子树之后，或直接作为第一个子项插入，并在预览中保持层级稳定。

#### P2-5 footer 的“已到底”和“还有 N 条”会互相矛盾

- 位置：`src/widget/WidgetApp.tsx:107-111`、`159-167`
- 实测 1：紧凑模式 3 条、共 8 条内容，未展开时滚轮滚动 100px，footer 变成“已到底”（仍有 5 条被 compact 限制隐藏）。
- 实测 2：展开 15 条、共 16 条内容，渲染 15 行，footer 初始“还有 1 条”；滚到底后变“已到底”，第 16 行永远不会渲染（`EXPANDED_METRICS {"clientHeight":432,"scrollHeight":574}`）。
- 说明：展开模式只显示 `expanded` 条属于规格设计；问题是“已到底”覆盖了“还有 N 条”，让用户以为内容已看完。
- 建议：滚动到底时仍优先显示剩余条数；紧凑模式禁用内容区滚动，或把可滚动区域限制到实际溢出的列表。

#### P2-6 数字输入框清空后立即跳到最小值

- 位置：`src/shared/settings.ts:170`、`src/editor/EditorApp.tsx:820-855`
- 实测：清空“宽度”输入框并失焦，值从 360 跳到 300；随后输入“400”可能拼成“300400”再被夹到 480。
- 建议：受控输入允许临时空串，失焦或提交时再 clamp；`onChange` 只解析有效数字。

#### P2-7 保存失败后不会自动重试

- 位置：`src/editor/EditorApp.tsx:297-303`
- 现象：自动保存 effect 依赖 `[dirty, text, readOnlyReason]`。保存失败后这些值不变，因此不会再次触发；用户必须手动点保存或继续输入。
- 建议：保存失败后按退避重试（例如 2s/5s/15s），或至少在状态栏提供“重试”。

#### P2-8 组件首次加载失败会永久停在“加载中…”

- 位置：`src/widget/WidgetApp.tsx:32-52`
- 现象：`loadSnapshot()` 抛错时只保留加载态，没有错误提示或重试。
- 可触发场景：默认文件路径存在但不可读（权限/被占用）、后端初始化失败。
- 建议：显示“读取失败”与“重试/打开编辑器”操作，并保留上一次成功快照（如果有）。

### 12.2 P1 详情

#### R2-P1-1 文件被移动/删除后伪装成空文件

- 位置：`src-tauri/src/lib.rs:269-295`（`ensure_current`）、`:398-403`、`:438`（`save_markdown`）；`src/widget/WidgetApp.tsx:159-174`
- 规格：`Sotto.md:124`（组件错误态、编辑器提示重新选择、草稿保留）、`:352`（文件不存在 · 请重新选择）
- 现状：文件不存在时 `ensure_current` 返回 `empty_file(path)`，快照里没有“缺失”标志；组件按空文本显示“文件为空 · 点铅笔打开编辑器”，编辑器显示空文档并标记“已加载”。
- 进一步：编辑器保存时 `exists == false`，`disk_hash` 与空文件哈希一致，于是直接在旧路径创建新文件。若原文件是被移动/重命名，用户会得到一个空的新文件，且不知道原文件在哪。
- 复现（代码路径）：重命名 `Documents\Sotto.md` → watcher 触发 `file-changed` → `ensure_current` 返回空文本 → 组件/编辑器显示空；在编辑器输入并保存 → 旧路径被重建。
- 建议：快照增加 `missing`/`error` 状态；组件显示“文件不存在 · 请重新选择”；编辑器显示横幅并提供“重新选择文件”，保存前禁止静默重建；已有草稿保留并可另存。

#### R2-P1-2 展开高度不按工作区计算

- 位置：`src/widget/widget.css:148-154`（`max-height: min(rows*38px, 60vh)`）、`src-tauri/src/lib.rs:1229`（固定 `384×520`）、`:745-768`（只做夹回，不做按内容/方向调整）
- 规格：`Sotto.md:326-333`（`height = min(expanded 条数对应高度, 工作区 60%, 窗口下方可用空间)`；下方不足 3 条向上展开）
- 浏览器实测（960×720）：紧凑卡片 192px、展开 510px，而 60% 视口为 432px，展开已超过上限。
- 原生推算（窗口 384×520 逻辑）：`60vh = 312px`，列表视口最多 312px，等于 8.2 行；卡片高约 388px，窗口剩余 132px 透明空白。用户设置 `expanded = 15` 时仍只能看到 8 行，必须滚轮。
- 说明：`60vh` 是窗口高度而不是工作区高度；原生窗口不会随展开调整大小，也不会检测下方空间。
- 建议：由前端把目标卡片高度/展开方向告知 Rust，按工作区 60% 与下方可用空间计算并 `set_size`/`set_position`；紧凑与展开都使用同一套高度公式。

### 12.3 P2 详情

#### R2-P2-1 大文件切换保留完整预览

- 位置：`src/editor/EditorApp.tsx:122-152`（`applySnapshot` 不重置 `previewMode`）、`:163-185`（选择文件后直接 `applySnapshot`）、`:703-706`（`previewMode === 'full'` 时同步 `renderFullMarkdown(text)`）
- 规格：`Sotto.md:402-403`（打开文件时静态判断，>2000 行或 >512KB 直接任务专用视图）
- 实测：先在 `# T` 文件点“完整预览”，再通过文件输入加载 600KB `big.md`；`.editor-large-note` 出现，但完整预览仍是活动页签并渲染出 614,405 字符。
- 影响：大文件会被同步渲染；真实 WebView 下可能卡住主线程，而规格要求的是先降级、再由用户主动加载完整预览。
- 建议：`applySnapshot`/`applyTextSwitch` 在新文件超过阈值时强制 `setPreviewMode('tasks')`；只在用户点击“加载完整预览”后进入 full。

#### R2-P2-2 Shift+Tab 只处理选区第一行

- 位置：`src/editor/EditorApp.tsx:489-497`
- 规格：`Sotto.md:407`（Shift+Tab 反缩进）
- 实测：`    - [ ] a\n    - [ ] b\n`，从第一行中间选到第二行末尾，按 Shift+Tab 后得到 `"  - [ ] a\n    - [ ] b\n"`：第一行只删了 2 个空格，第二行完全没动。
- 原因：只取 `selectionStart` 所在行、只删 `selectionStart` 前的空格，没有按选中行逐行处理。
- 建议：与 Tab 的多行逻辑对称：按 `lineStart`/`blockEnd` 拆行，对每行去掉最多 4 个前导空格，并用 `setRangeText(..., 'select')` 保持选区。

#### R2-P2-3 IME 组合输入期间仍会触发自动保存

- 位置：`src/editor/EditorApp.tsx:316-322`（effect 只在调度时检查 `composingRef`）、`:340`（保存读取 `textarea.value`）、`:474-476`（`compositionstart` 只置位，不取消计时器）
- 规格：`Sotto.md:187`（compositionstart 暂停自动保存和预览同步，compositionend 后重启计时）
- 实测：输入 `x` 启动 1 秒计时器 → 100ms 后派发 `compositionstart` 并让 textarea 包含组合文字 `中`（不再产生 input）→ 1 秒后 localStorage 变成 `- [ ] ax中`；此时预览仍显示 `a`。若用户随后取消组合（textarea 回到 `ax`），磁盘上已留下 `中`。
- 说明：真实输入法通常会在组合过程中触发 input，从而重置计时器；但只要用户开始组合后停顿超过剩余等待时间，就会命中该窗口。
- 建议：`compositionstart` 时清除已排队的保存/预览计时器（或让计时器回调再次检查 `composingRef`），`compositionend` 后重新调度。

#### R2-P2-4 列表内 4 空格围栏代码块泄漏任务

- 位置：`src/shared/taskParser.ts:5`（FENCE 只允许 0–3 个前导空格）、`:59-71`、`:87-90`（顶层缩进检查只对空栈生效）
- 实测：

  ````text
  - [ ] 父项
      ```
      - [ ] 假任务
      ```
  - [ ] 真任务
  ````

  解析结果任务为 `["父项","假任务","真任务"]`，内容里出现围栏文本行；组件进度 0/3，而不是 0/2。
- 建议：围栏识别改为相对当前列表项的缩进（记录列表容器列），或在列表内允许 4 空格围栏；围栏内的所有行一律跳过。

#### R2-P2-5 HTML 注释中的任务泄漏

- 位置：`src/shared/taskParser.ts:56-140`（没有 HTML 块状态）
- 实测：`<!--\n- [ ] 注释里的任务\n-->\n- [ ] 真任务` → 任务为 `["注释里的任务","真任务"]`，内容为 `["<!--","注释里的任务","-->","真任务"]`；组件在紧凑模式显示注释标记和注释任务，进度 0/4（含后续代码块任务）。
- 建议：识别 `<!-- ... -->` 块（包括单行）并整块跳过；不要输出注释标记。

#### R2-P2-6 缺少新建、另存为、另存草稿和重试入口

- 位置：`src/editor/EditorApp.tsx:714-754`（顶栏只有“选择文件/最近文件/保存/关闭”）、`:770-776`（冲突栏只有重新加载/覆盖保存）、`:992-999`（状态栏只有保存状态文本）、`:1058-1075`（重新加载确认只有放弃/取消）
- 规格：`Sotto.md:122`（只读允许另存为）、`:202`（重新加载前提供另存草稿）、`:203`（error 显示重试/另存为）、`:399`（选择已有 .md 或新建）、`:408`（状态栏重试）
- 现状：没有“新建”；没有“另存为”；冲突重新加载确认没有“另存草稿”；保存失败时状态栏没有可点击的“重试”（第一轮 P2-7 已指出不会自动重试）。
- 影响：只读/超大文件中的编辑无法保存到别处；冲突时想保留草稿只能复制文本；文件误删场景也缺少“另存为”出口。
- 建议：至少补“新建”（默认 Documents 下新文件名 + 模板）和“另存为”；冲突重载对话框加“另存草稿”；错误状态提供“重试”按钮，复用 `persistNow`。

#### R2-P2-7 读取错误被静默吞掉

- 位置：`src-tauri/src/lib.rs:278-286`
- 规格：`Sotto.md:354`（读取错误 · 无法读取文件 · 打开编辑器查看详情）
- 现状：`load_file` 失败且存在缓存时直接返回缓存，快照没有错误字段；组件继续显示旧内容，没有任何异常提示。只有“无缓存且读失败”才会向上抛错，而组件首载失败会停在“加载中…”（第一轮 P2-8）。
- 建议：快照增加 `readError`，保留缓存内容但显示横幅/状态；组件提供“重试读取”。

#### R2-P2-8 会话结束没有强制落盘

- 位置：`src-tauri/src/lib.rs:843-857`（托盘退出路径）、全局 grep 无 `WM_QUERYENDSESSION`
- 规格：`Sotto.md:205`、`:475`（`WM_QUERYENDSESSION` 强制落盘并记录失败）
- 现状：托盘退出会先让编辑窗口走关闭确认；但 Windows 关机/注销不会走这条路径，编辑窗口内的草稿只有 1 秒自动保存（最近 1 秒内的输入可能丢失），也没有失败日志。
- 建议：在窗口 `hwnd` 上处理 `WM_QUERYENDSESSION`，同步刷出当前草稿并记录结果；无法落盘时允许阻止关机或至少写日志。
